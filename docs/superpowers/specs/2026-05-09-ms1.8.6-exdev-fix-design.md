# MS1.8.6 — EXDEV fix in `fetchActionFromCanonical` — Design

**Date:** 2026-05-09
**Status:** Designed; implementation pending on `fix/ms1.8.6-exdev`.
**Driver:** muninn `01KR4XXZG6EG5XAHKCDQV9PHDQ` (`runtime-fetch-rename-exdev`) — bug
surfaced by the smoke driver after MS1.8.5 landed.

## Goal

Eliminate the `EXDEV` failure that kills `aia install` (and the
`scripts/smoke-claude-agent.ts` smoke driver) on any host where the
default `os.tmpdir()` and the registry root (`~/.aiactions/actions/...`)
live on different filesystems — notably Linux Fedora, where `/tmp` is a
tmpfs by default while `$HOME` is on the root filesystem.

## Non-goals

- Orphan-directory cleanup under `<registryRoot>/.tmp/` after a crash.
  Sparse `--filter=blob:none` clones are tiny (KBs); a sweeper is YAGNI
  until we observe accumulation in practice.
- Cross-platform integration coverage of the EXDEV scenario itself.
  Constructing a deterministic cross-fs setup in CI is fragile; an
  invariant-style unit test gives equivalent regression protection.
- Changes to the public `FetchActionFromCanonicalOptions` /
  `EnsureCachedActionOptions` shapes. Callers that pass `tmpRoot`
  explicitly keep the exact same semantics.

## Decisions

### D1. `tmpRoot` defaults to `<registryRoot>/.tmp/` (was `os.tmpdir()`)

`fetchActionFromCanonical` performs a sparse `git clone` into a
`mkdtemp` directory under `tmpRoot`, then moves the resolved action
subtree to its final cache directory with `fs.rename`. POSIX
`rename(2)` is atomic but **only intra-filesystem** — across
filesystems it fails with `EXDEV`. By defaulting `tmpRoot` to a
sub-directory of `registryRoot`, the clone always lives on the same
filesystem as the destination, so `rename` keeps its atomic semantics
without copy fallbacks.

Three alternatives were evaluated:

| Option                                                           | Atomicity     | Copy cost | Surface                                            |
| ---------------------------------------------------------------- | ------------- | --------- | -------------------------------------------------- |
| **A** (chosen) — same-fs default `tmpRoot`                       | atomic rename | none      | one-line default change                            |
| B — `fs.cp` recursive then `rm`                                  | non-atomic    | full copy | replaces rename + adds partial-state risk on crash |
| C — `fs.cp` into sibling under `registryRoot` then atomic rename | atomic rename | full copy | larger refactor, no win over A                     |

A wins on every axis. The argument against — "tmp clutter under the
registry root" — is mitigated by the existing `try…finally rm(tmp,
{ recursive: true, force: true })` cleanup; only crashes leak orphans,
and clones are kilobytes.

### D2. The default change is sticky for the whole helper

The `tmpRoot` option remains accepted for callers that want to pin tmp
elsewhere (existing tests do this to keep registry and tmp under a
single `mkdtemp` work directory). But the default is now coupled to
`registryRoot`, so the function does
`tmpRoot = options.tmpRoot ?? join(registryRoot, ".tmp")`. The
`mkdir(tmpRoot, { recursive: true })` already present handles the
"first ever fetch on a fresh machine" case, where neither
`<registryRoot>` nor `<registryRoot>/.tmp` exists yet.

### D3. Regression coverage is an invariant test, not an integration test

The bug class is "rename across filesystems." Once `tmp` is guaranteed
intra-filesystem with the destination, the class is gone by
construction. The regression test asserts that invariant directly:
calling `fetchActionFromCanonical` without an explicit `tmpRoot`
results in a tmp directory created **under** `<registryRoot>/.tmp/`.
This is deterministic, network-free, and immune to CI filesystem
variance.

The smoke driver (`scripts/smoke-claude-agent.ts`) provides the
end-to-end signal — it was the canary that surfaced the bug, and a
post-fix run is the acceptance gate for the milestone.

### D4. Release shape: patch bump, single-component squash

Only `packages/runtime/src/runner/uses/registry-fetch.ts` and its
co-located test changes. Conventional Commit:

```
fix(runtime): default tmpRoot to <registryRoot>/.tmp to avoid EXDEV across filesystems
```

`release-please` routes this to `@aiactions/runtime` 3.0.0 → 3.0.1.
No workspace-dep ripple expected (the public API surface is unchanged).
No CHANGELOG hand-edit; release-please owns it.

## Implications for downstream milestones

- The smoke driver becomes reliable again as a regression canary post-
  MS1.8.6, unblocking the MS1.9 brainstorm (`aia workflow check`)
  whose prerequisite — `workflow-discovery-roots` — depends on a
  green smoke baseline to validate end-to-end behaviour.
- Future "registry hygiene" features (orphan tmp sweep, age-based
  cache eviction, integrity checks) now have a single canonical home
  to land in: `<registryRoot>/.tmp/` and `<registryRoot>/<ns>/<name>/`.
  Worth flagging as MS1.10+ candidates rather than scope-creeping into
  this fix.
