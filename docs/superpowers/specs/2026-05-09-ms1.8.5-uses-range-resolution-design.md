## Context

After the `vv1` parser bug was fixed (commit `610cc49`), the smoke driver progressed past `usesRefSchema` and `fetchActionFromCanonical`'s tag construction, then failed at the actual `git clone --branch claude/agent@v1` step:

```
fatal: La branche distante claude/agent@v1 n'a pas été trouvée dans le dépôt amont origin
```

Root cause: the canonical `aiactions` repo only publishes concrete semver tags (`claude/agent@v1.0.0`). There is no floating `claude/agent@v1` major-version tag, so any `uses: claude/agent@v1` in a workflow yaml fails at clone time.

This is a **runtime feature gap**, not a bug in any specific module. AIactions inherits the GitHub Actions convention of `@v1` shorthand referring to "latest matching major" but currently has no resolver to map that shorthand to a concrete tag.

## Goals

1. **`uses: claude/agent@v1`** in a workflow yaml resolves automatically to the highest published `claude/agent@v1.x.y` tag, with no infrastructure outside the runtime (no floating tags, no GitHub Action workflows, no registry-side rewrites).
2. **Determinism across machines** — once resolved on machine A, the same concrete version is reused on machine B (fresh checkout) when the workflow + lockfile are committed together. Resolution happens once, on first install; subsequent runs read the lockfile.
3. **Same UX for the CLI installer** — `aia action install claude/agent@v1` resolves the same way without new code on the CLI side (the runtime layer takes care of it).
4. **No external infra dependency** — keeps with the project's "local-only at runtime" hard constraint. No release-please customisation to maintain floating tags.

## Non-goals

- Full semver range syntax (`@^1.0.0`, `@~1.2`, `@>=1`). Out of scope for MS1.8.5 — only `@v1` major-prefix and `@v1.0.0` exact are supported. Adding richer ranges later is additive.
- Pre-release tags in major-range matching (`@v1.3.0-beta.1`). Pre-releases are excluded from major-range pickers; explicit-exact still works (`@v1.3.0-beta.1`).
- Drift detection on lockfile-pinned shas (e.g. force-pushed retags). YAGNI — single dev locally, no concrete attack surface yet. Re-add when needed.
- Lockfile auto-migration v1 → v2 entry-by-entry. Strict version mismatch error, user deletes the v1 file and re-runs. Acceptable because **no external users today** (project shipped MS1.8 within hours).

## Architecture

### Call chain

`resolveUsesRef` (`packages/runtime/src/runner/uses/resolver.ts`) calls `ensureCachedAction` (`packages/runtime/src/runner/uses/registry-fetch.ts`) for registry refs. The new flow inside `ensureCachedAction`:

```
ensureCachedAction(ref, registryRoot, cwd, options)
├── readLockfile(cwd) → lock                                            // existing
├── lockKey = `${ref.namespace}/${ref.name}@${ref.version}`
├── lockEntry = lock.actions[lockKey]
│   ├── HIT
│   │   ├── cacheDir = join(registryRoot, ns, name, lockEntry.resolvedVersion)
│   │   ├── stat(cacheDir) HIT  → return { dir, fetched: false, resolvedSha }
│   │   └── stat(cacheDir) MISS → fetchActionFromCanonical(
│   │           { ...ref, version: lockEntry.resolvedVersion },
│   │           registryRoot,
│   │           options,
│   │       )
│   │       → return { dir: cacheDir, fetched: true, resolvedSha }
│   └── MISS
│       ├── classify(ref.version)
│       │   ├── "exact" → fetchActionFromCanonical(ref, ...)            // unchanged
│       │   ├── "major" → resolved = await resolveMajorRange(ref, canonicalUrl)
│       │   │           → fetchActionFromCanonical(
│       │   │                 { ...ref, version: resolved.resolvedVersion },
│       │   │                 ...,
│       │   │             )
│       │   └── "branch" → fetchActionFromCanonical(ref, ...)           // unchanged
│       ├── upsertLockfileEntry(cwd, ref, { resolvedVersion, resolvedSha })
│       └── return { dir, fetched: true, resolvedSha }
```

Key invariants:

- Range resolution (`resolveMajorRange`) runs **only on lockfile miss**. Once pinned, deterministic re-installs use the lockfile alone.
- `fetchActionFromCanonical` always receives a concrete version (no range), keeping its contract simple — its tag construction `${ns}/${name}@v${ref.version}` already works for concrete semver.

### `resolveMajorRange`

New helper in `packages/runtime/src/runner/uses/registry-fetch.ts` (or split into `resolve-range.ts` if the file grows past ~300 lines):

```ts
export async function resolveMajorRange(
  ref: RegistryCoordinate,
  canonicalUrl: string,
): Promise<{ resolvedVersion: string; resolvedSha: string }> {
  const major = parseInt(ref.version, 10);
  const { stdout } = await pExecFile("git", ["ls-remote", "--tags", canonicalUrl]);

  const TAG_PREFIX = `refs/tags/${ref.namespace}/${ref.name}@v`;
  const SEMVER_RE = /^(\d+)\.(\d+)\.(\d+)$/u; // stable only — no pre-release

  const candidates: { version: string; sha: string }[] = [];
  for (const line of stdout.trim().split("\n")) {
    const [sha, fullRef] = line.split("\t");
    if (!fullRef?.startsWith(TAG_PREFIX)) continue;
    const versionPart = fullRef.slice(TAG_PREFIX.length).replace(/\^\{\}$/u, "");
    const m = SEMVER_RE.exec(versionPart);
    if (!m || parseInt(m[1]!, 10) !== major) continue;
    candidates.push({ version: versionPart, sha: sha!.trim() });
  }

  if (candidates.length === 0) {
    throw new ActionResolutionError(
      `no published version of '${ref.namespace}/${ref.name}' matches major '^${major}.0.0' at ${canonicalUrl}`,
    );
  }

  candidates.sort((a, b) => semverRcompare(a.version, b.version));
  return { resolvedVersion: candidates[0]!.version, resolvedSha: candidates[0]!.sha };
}
```

Notes:

- `^\{\}$` strip handles dereference-tag entries that `git ls-remote --tags` emits for annotated tags.
- Only `MAJOR.MINOR.PATCH` (3-segment, all-digit, no pre-release suffix) tags are accepted as range candidates. Pre-releases must be opted-in via exact ref.
- `semverRcompare` is `import { rcompare as semverRcompare } from "semver"` — same dep already used by the CLI registry layer.

### `classify`

Helper to decide which path to take:

```ts
const EXACT_SEMVER_RE = /^\d+\.\d+\.\d+(?:-[\w.-]+)?$/u;
const MAJOR_ONLY_RE = /^\d+$/u;

type VersionClass = "exact" | "major" | "branch";

export function classifyVersion(version: string): VersionClass {
  if (EXACT_SEMVER_RE.test(version)) return "exact";
  if (MAJOR_ONLY_RE.test(version)) return "major";
  return "branch";
}
```

Branch is the default — anything not matching the two semver shapes is treated as a literal git ref (tag or branch name). `fetchActionFromCanonical` already handles arbitrary refs via `git clone --branch <ref>`.

## Lockfile schema v1 → v2

### v2 shape

```ts
const lockfileV2 = z.strictObject({
  version: z.literal(2),
  actions: z.record(
    z.string(),
    z.strictObject({
      resolvedVersion: z.string().min(1),
      resolvedSha: z.string().min(1),
    }),
  ),
});
```

Compared to v1 (MS1.8): adds `resolvedVersion` to each entry. The key remains `<ns>/<name>@<userRef>` where `<userRef>` is the post-parser-strip version literal (e.g. `1`, `1.0.0`, `main`).

Example post-resolution lockfile after smoke run:

```json
{
  "version": 2,
  "actions": {
    "claude/agent@1": {
      "resolvedVersion": "1.0.0",
      "resolvedSha": "<sha>"
    }
  }
}
```

### Migration policy

- **No auto-migration.** `readLockfile` parses with `lockfileV2.strict()`. If the file's `version !== 2`, throw `LockfileVersionMismatch` with an explicit message:
  > `lockfile uses schema v<X>, expected v2. Delete .aiactions/lock.json and re-run to regenerate.`
- Acceptable cost: project shipped MS1.8 within hours of MS1.8.5; only one local dev; no committed v1 lockfiles in the wild.

### Implementation impact

- `packages/runtime/src/lockfile.ts` — bump `CURRENT_VERSION = 2`, update Zod `lockfileSchemaV1` (rename to `lockfileSchemaV2`), update `LockfileEntry` interface to include `resolvedVersion`.
- `UpsertLockfileEntryRequest` interface picks up the new field; callers in `ensureCachedAction` are updated to pass it.

The schema lives entirely in `packages/runtime/src/lockfile.ts` (verified 2026-05-09). No `@aiactions/workflows` package change required for the lockfile.

## Error handling

| Cause                                | Where                                 | Error type                                 | Message                                                                           |
| ------------------------------------ | ------------------------------------- | ------------------------------------------ | --------------------------------------------------------------------------------- |
| Lockfile schema mismatch             | `readLockfile`                        | `LockfileVersionMismatch`                  | `lockfile uses schema v<X>, expected v2. Delete .aiactions/lock.json and re-run.` |
| `git ls-remote` fails                | `resolveMajorRange`                   | `ActionResolutionError`                    | `failed to list tags for '<ns>/<name>' at <url>: <stderr>`                        |
| No matching major                    | `resolveMajorRange`                   | `ActionResolutionError`                    | `no published version of '<ns>/<name>' matches major '^<X>.0.0' at <url>`         |
| Lockfile-pinned tag missing upstream | `fetchActionFromCanonical` (existing) | `ActionResolutionError`                    | existing message, kept (no new layer)                                             |
| Pre-release-only matches             | `resolveMajorRange`                   | `ActionResolutionError` (same as no-match) | same as "no matching major" — pre-releases never count                            |

Drift detection (lockfile-pinned sha mismatches upstream HEAD on re-fetch) is intentionally **deferred** to a future MS. The current single-dev local context does not justify the added complexity.

## Risk + rollback

- **Risk**: range resolution adds a network round-trip (`git ls-remote --tags`) on first install. Mitigated by lockfile pinning — only first run pays the cost.
- **Risk**: schema bump v1 → v2 invalidates any committed v1 lockfile. Mitigated by hard requirement that no external users exist today.
- **Rollback**: revert all MS1.8.5 commits; lockfile reverts to v1 shape; range refs (`@v1`) start failing again at `fetchActionFromCanonical` — **same failure mode as today**. No new corrupted state, no migration-out cost.

## Out-of-scope (deferred)

- Minor-prefix range (`@v1.2` → highest `1.2.x`). Add when a real workflow needs it.
- `^` / `~` / `>=` semver operators in `uses:` strings. Same.
- Pre-release support in major-range matching. Add via opt-in flag (`@v1-prerelease`?) when needed.
- Drift detection / `.aiactions/lock.json` integrity guard.
- Lockfile entry-by-entry v1 → v2 auto-migration.
- Multi-canonical-source resolution (currently one canonical per registry root).
