## 1. Context and motivation

MS1.5 shipped the actions registry backend. `actions/registry.json` is published at the canonical raw URL `https://raw.githubusercontent.com/Aperrix/aiactions/main/actions/registry.json` and regenerated by CI on merge to `main`. The schema today is `{ actions: [{ ref: "<ns>/<name>@<ver>", description: "..." }] }`.

MS1.6 wires the `@aiactions/cli` frontend to that backend. Today the CLI has three action verbs (`install`, `list`, `uninstall`), but `install` only accepts an explicit `<ns>/<name>@<ver>` and `list` only sees the local cache. MS1.6 lifts those limits so the registry is the discovery surface for end users.

This spec is the validated design after the brainstorm phase. Implementation plan follows in a separate document.

## 2. Scope

In scope (three CLI surface changes):

1. `aia action install <ns>/<name>` (no version) — short form resolves to the highest-semver `<ns>/<name>@<ver>` in the registry.
2. `aia action install` (no argument) — interactive multi-select picker fed by registry entries, latest version per `<ns>/<name>`.
3. `aia action list` — union of registry view and local cache, with `[installed]` / `[installed, registry has @<latest>]` badges and a `Local only:` section for cache-only refs. Adds a `--json` flag.

Out of scope:

- Persistent on-disk cache for the fetched registry (always-fresh policy).
- Bare-name short form `aia action install <name>` (no namespace) — explicitly rejected to avoid ambiguity.
- Version pinning inside the no-arg picker — defer until at least one user request.
- Authenticated registries / private registries — runtime is local-only and the public registry is the only consumer surface today.
- Tooling for the picker UX (interactive smoke tests) — covered by manual verification.
- A new `@aiactions/registry` package — premature; revisit when a third caller appears.

## 3. Decisions (locked in brainstorm)

### 3.1 Registry cache strategy — always-fresh

Each CLI invocation fetches `registry.json` over HTTP at most once and never persists it. Rationale: payload is sub-KB, network is rarely the bottleneck for an interactive dev command, and predictable cache-free behavior beats latency optimization at this scale. We can layer a TTL or ETag cache later if observed latency becomes a problem.

### 3.2 Network-failure policy — skip the registry fetch when not required

The CLI distinguishes two network operations:

- _Registry fetch_ — needed for short-name resolution (Flow B), the no-arg picker (Flow C), and the registry view of `list` (Flow D).
- _Action fetch_ — needed for any uncached install. Already implemented inside `ensureCachedAction` (`@aiactions/runtime`). Out of scope for this milestone.

Policy:

| Command form | Registry fetch | Behavior on registry failure |
| --- | --- | --- |
| `install <ns>/<name>@<ver>` | not performed | unaffected (action fetch only) |
| `install <ns>/<name>` | required | hard fail with exit `REGISTRY` |
| `install` (no arg) | required | hard fail with exit `REGISTRY` |
| `list` | best-effort | degrade to local-only with stderr warning, exit 0 |

Rationale: a fully-qualified ref is self-describing — there is no reason to round-trip the registry. Short-name resolution and the picker have a hard dependency on the registry, so a failure must be loud. `list` stays useful when offline because inspecting the local cache is its primary value.

### 3.3 Short-name semantics — `<ns>/<name>` only

`aia action install <ns>/<name>` resolves to the highest-semver entry of `<ns>/<name>@*` in the registry. Bare `aia action install <name>` (no namespace) is rejected with `UsageError` and a message pointing at the `<ns>/<name>` form. The picker covers the discovery use case where the user does not know the namespace.

Rationale: avoids retroactive ambiguity. Today only `claude/agent` exists; tomorrow `openai/agent` could exist. A bare-name shortcut would silently change resolution for a user who scripted `aia action install agent`. Aligns with `actions/checkout@v4` ergonomics.

### 3.4 Picker shape — latest-only multi-select

`aia action install` (no arg) presents one row per `<ns>/<name>`, displaying the latest registry version and the description. Selection is multi-select (clack `multiselect`). For each chosen row, the CLI installs the latest version. Pinning a specific version goes through the explicit `<ns>/<name>@<ver>` form.

Rationale: avoids a two-stage prompt that adds friction for the 99% case (installing latest). Non-breaking to extend later if version pinning becomes a frequent ask.

### 3.5 `list` output — single section with badges

Single-section human output, ordered alphabetically by coord. Format:

```
<ns>/<name>@<latest-from-registry>  — <description>            [installed]
<ns>/<name>@<latest-from-registry>  — <description>            [installed, registry has @<other-latest>]   ← outdated
<ns>/<name>@<latest-from-registry>  — <description>

Local only:
  <ns>/<name>@<cached-ver>
```

Notes:

- `[installed]` ⇔ the cache contains the registry's latest version.
- The `[installed, registry has @<latest>]` form is rendered when the cache has at least one version of `<ns>/<name>` but none of them matches latest. The version shown on the left is the latest registry version (the upgrade target); the cached version is named in the badge.
- `Local only:` lists cached refs (full `<ns>/<name>@<ver>`) that are absent from the registry.
- `--json` mode emits a parsable shape (see Section 6).

## 4. Architecture

```
packages/workflows/src/schema/registry.ts        ← NEW: Zod schema + types
   re-exported from packages/workflows/src/index.ts

scripts/gen-actions-registry.ts                  ← MODIFIED: validate emit via Zod schema

packages/cli/src/lib/registry.ts                 ← NEW: HTTP fetch + resolution helpers
packages/cli/src/lib/list-cached.ts              ← NEW: scan local registry root for cached refs
packages/cli/src/lib/exit-codes.ts               ← MODIFIED: add EXIT.REGISTRY
packages/cli/src/lib/errors.ts                   ← MODIFIED: add registry/ambiguity error classes

packages/cli/src/commands/action/install.ts      ← MODIFIED: short-name + no-arg picker
packages/cli/src/commands/action/list.ts         ← MODIFIED: registry union + badges + --json
```

Boundaries:

- `@aiactions/workflows` owns schemas (manifest + registry). Pure validators. No I/O, no network.
- `packages/cli/src/lib/registry.ts` is the HTTP adapter and the only place that knows the canonical URL and how to validate the payload. No business logic beyond fetch and index.
- `packages/cli/src/lib/list-cached.ts` is the cache scanner. Independent of the registry.
- Commands stay thin — they orchestrate `lib/registry`, `lib/list-cached`, and `@aiactions/runtime`'s `ensureCachedAction`.

## 5. Components

### 5.1 `@aiactions/workflows` — `schema/registry.ts`

```ts
import { z } from "zod";

export const registryEntrySchema = z.object({
  ref: z.string().regex(/^[a-z][a-z0-9-]*\/[a-z][a-z0-9-]*@\d+\.\d+\.\d+(?:-[\w.-]+)?$/),
  description: z.string().min(1),
});
export type RegistryEntry = z.infer<typeof registryEntrySchema>;

export const registrySchema = z.object({
  actions: z.array(registryEntrySchema),
});
export type Registry = z.infer<typeof registrySchema>;
```

The regex matches the production constraint already enforced by the emitter (lowercase namespace, lowercase name, semver with optional pre-release). Refine if integration tests reveal a mismatch.

### 5.2 `packages/cli/src/lib/registry.ts`

```ts
export const REGISTRY_URL_DEFAULT =
  "https://raw.githubusercontent.com/Aperrix/aiactions/main/actions/registry.json";

export function resolveRegistryUrl(env: NodeJS.ProcessEnv): string;

export async function fetchRegistry(url?: string): Promise<Registry>;

export function resolveLatest(reg: Registry, ns: string, name: string): RegistryEntry | null;

export function groupByCoord(reg: Registry): Map<string, RegistryEntry[]>;
```

- `resolveRegistryUrl` honors `AIACTIONS_REGISTRY_URL` over the default.
- `fetchRegistry` performs `GET`, parses JSON, validates with `registrySchema`. Throws `RegistryFetchError` on transport failure or non-2xx. Throws `RegistryValidationError` on JSON or Zod failure. Timeout 10s.
- `resolveLatest` returns the highest-semver entry for `<ns>/<name>` or `null`. Pre-releases follow standard semver precedence (lower than the same MAJOR.MINOR.PATCH stable).
- `groupByCoord` returns a `Map` keyed on `"<ns>/<name>"`, values sorted by semver descending.

### 5.3 `packages/cli/src/lib/list-cached.ts`

```ts
export interface CachedRef {
  readonly ns: string;
  readonly name: string;
  readonly version: string;
  readonly dir: string;
}

export async function listCachedActions(registryRoot: string): Promise<CachedRef[]>;
```

Walks `<registryRoot>/<ns>/<name>/<ver>/`. Skips entries that do not parse against the same regex as the registry schema. Returns a flat list, sorted by `<ns>/<name>@<ver>`.

### 5.4 `packages/cli/src/lib/errors.ts` (additions)

```ts
export class RegistryFetchError extends CliError { /* exit code REGISTRY */ }
export class RegistryValidationError extends CliError { /* exit code REGISTRY */ }
```

The bare-name path (e.g., `aia action install agent`) throws the existing `UsageError` directly. No new class is introduced for ambiguity because the locked short-name form (`<ns>/<name>`) cannot be ambiguous by construction.

### 5.5 `packages/cli/src/lib/exit-codes.ts` (additions)

Add `REGISTRY` (numeric value selected at implementation time, distinct from existing codes).

### 5.6 Command diffs

#### `commands/action/install.ts`

- `args.ref` becomes optional.
- Branch on the input:
  - `undefined` → no-arg picker (Flow C).
  - matches `<ns>/<name>@<ver>` → existing path (Flow A).
  - matches `<ns>/<name>` (no `@`) → registry-resolved path (Flow B).
  - anything else → `UsageError`.
- After resolution, all three paths converge on `ensureCachedAction(...)` and emit identical success or JSON output.

#### `commands/action/list.ts`

- Replace existing implementation with: `fetchRegistry().catch(null)` → `listCachedActions(registryRoot)` → join → render. `--json` toggles output mode.

## 6. Data flow

### 6.1 Flow A — `install <ns>/<name>@<ver>` (explicit)

```
parseRegistryRef(input) → { ns, name, version }
ensureCachedAction({ ns, name, version }, registryRoot, cwd, opts)
emit success | rethrow as CliError(EXIT.RUNTIME)
```

No registry fetch. Identical to MS1.4 behavior.

### 6.2 Flow B — `install <ns>/<name>` (short)

```
parseShortRef(input) → { ns, name }                 // new helper, complements parseRegistryRef
fetchRegistry()                                     // throws RegistryFetchError | RegistryValidationError
resolveLatest(reg, ns, name) → entry | null
  null  → throw NotFoundError(`no action '${ns}/${name}' in registry`)
  entry → parseRegistryRef(entry.ref) → { ns, name, version }
ensureCachedAction(...)
emit success
```

### 6.3 Flow C — `install` (no arg → picker)

```
fetchRegistry()                                     // throws on fail (no offline picker)
groupByCoord(reg) → Map<coord, entries>
rows = for each coord, take entries[0] (latest)
selected = clack.multiselect(rows)
selected.length === 0 → exit 0 (silent cancel)
for each entry of selected:
  parseRegistryRef(entry.ref) → coords
  ensureCachedAction(...) → emit one human or JSON line per result
```

### 6.4 Flow D — `list`

```
const reg = await fetchRegistry().catch(err => ({ ok: false, err }))
const cached = await listCachedActions(registryRoot)

const rows = joinRegistryAndCache(reg, cached)
   row = {
     coord: "<ns>/<name>",
     latest: string | null,        // null if registry unreachable or coord absent
     installedVersions: string[],  // versions present in cache
     description: string | null,
     localOnly: boolean,           // true if coord is in cache but absent from registry
   }

if (!reg.ok) emit warning("registry unreachable: <cause>; showing local only") on stderr
render rows in human or JSON mode
```

### 6.5 `--json` output shape for `list`

```json
{
  "registry": { "url": "...", "fetchedAt": "ISO-8601" } | null,
  "registryError": "string" | null,
  "entries": [
    {
      "coord": "<ns>/<name>",
      "latestRegistry": "1.0.0" | null,
      "installedVersions": ["1.0.0"],
      "description": "..." | null,
      "localOnly": false
    }
  ]
}
```

`registry` and `registryError` are mutually exclusive: exactly one is non-null.

## 7. Error handling

| Error | Exit code | Trigger | User-visible message |
| --- | --- | --- | --- |
| `RegistryFetchError` | `EXIT.REGISTRY` | Network failure, non-2xx, timeout | `failed to fetch registry from <url>: <cause>` |
| `RegistryValidationError` | `EXIT.REGISTRY` | Malformed JSON, Zod issue | `registry at <url> is malformed: <Zod issue>` |
| `NotFoundError` | `EXIT.NOT_FOUND` | Short-name path: coord absent from registry | `no action '<ns>/<name>' in registry. Run 'aia action list' to see available actions.` |
| `UsageError` | `EXIT.USAGE` | Bare name (no `<ns>/`), ref malformed | `expected '<ns>/<name>' or '<ns>/<name>@<ver>', got '<input>'` |

Per-command behavior:

- `install <ref>`:
  - `RegistryFetchError` / `RegistryValidationError` are only reachable on the short-name path (Flow B). The explicit ref path (Flow A) never hits the registry.
  - `ensureCachedAction` failures wrap into `CliError(EXIT.RUNTIME)`, unchanged.
- `install` (no arg):
  - Registry failure → throw (no picker is possible).
  - Empty selection → exit 0 silently (consistent with the existing uninstall picker).
- `list`:
  - Fetch failure → render warning on stderr, continue with cache only, exit 0.
  - Validation failure → identical UX (registry corrupt = registry unreachable from the user's point of view).
  - In `--json`, set `registry: null` and `registryError: "<msg>"` instead of writing to stderr.

Network policy:

- No automatic retry. Always-fresh implies at most one fetch per invocation; retry is the user's responsibility.
- HTTP timeout 10s. Beyond that → `RegistryFetchError` with `Error: timed out after 10s`.
- No auth header. The registry is public.

Guarantees:

- No silent error paths (fail-fast).
- A registry failure never mutates user state (no cache invalidation on the way out).
- All failure paths are integration-tested (Section 8).

## 8. Testing strategy

Per project rule (TDD value-over-dogma): tests must catch real failure modes or freeze externally-visible behavior. No tautological assertions, no tests coupled to implementation details.

### 8.1 Unit tests

- `packages/workflows/tests/registry-schema.test.ts` (new):
  - Valid registry parses; types infer correctly.
  - Invalid `ref` (missing `@`, missing `/`, uppercase, broken semver) raises a Zod issue.
  - Empty `actions: []` is accepted.
- `packages/cli/tests/registry.test.ts` (new):
  - `resolveRegistryUrl` honors `AIACTIONS_REGISTRY_URL` over the default.
  - `resolveLatest` returns the highest semver across multi-version entries; returns `null` when the coord is absent; respects pre-release precedence.
  - `groupByCoord` produces grouping with semver-desc ordering inside each bucket.
- `scripts/gen-actions-registry.test.ts` (modify):
  - Add `registrySchema.parse(emitted)` to confirm emitter and consumer agree on the shape.

### 8.2 Integration tests

Reusable HTTP mock = local `http.createServer()` bound to `port: 0`, URL injected via `AIACTIONS_REGISTRY_URL`. No external mocking library. Action tarball fetch reuses `packages/cli/tests/fixtures/make-bare-repo.ts` (existing pattern from MS1.4) so tests exercise `ensureCachedAction` against a real bare git repo.

- `packages/cli/tests/integration/install-registry.test.ts` (new):
  - Fixture registry with `claude/agent@1.0.0`, `foo/bar@2.0.0`, `foo/bar@2.1.0`.
  - `install foo/bar` → resolves `foo/bar@2.1.0`, downloads from a bare repo built by `make-bare-repo.ts`.
  - `install bar` (bare) → exit `USAGE` with the expected message.
  - `install nonexistent/x` → exit `NOT_FOUND`.
  - Registry server returns 500 → exit `REGISTRY` + clear message.
  - Registry server returns malformed JSON → exit `REGISTRY` + Zod issue in message.
- `packages/cli/tests/integration/list-registry.test.ts` (new):
  - Fixture HTTP server + cache pre-populated with one outdated ref and one local-only ref.
  - Healthy registry → output contains `[installed]`, `[installed, registry has @<latest>]`, and the `Local only:` section.
  - `--json` → shape matches Section 6.5.
  - Registry 500 → stderr warning + cached-only entries, exit 0.
  - `--json` + registry failure → `{ registry: null, registryError: "...", entries: [...] }`.

### 8.3 Out of scope for tests

- Interactive picker UX (clack multi-select) — fragile to mock; covered by manual verification at hand-off.
- HTTP timeout assertion — too slow for CI; covered by code review.
- `AIACTIONS_CANONICAL_URL` (action tarball URL) — already covered by runtime tests.

### 8.4 Verification gate

`vp run ready` must be green (typecheck + lint + tests + build) before commit. Identical pipeline to MS1.5.
