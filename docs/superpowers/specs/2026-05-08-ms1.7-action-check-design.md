# MS1.7 — `aia action check` design

**Status:** approved
**Date:** 2026-05-08
**Owner:** @aiactions/cli
**Depends on:** MS1.6 (CLI / registry / workflows already shipped)
**Spec format:** internal — see other specs under `docs/superpowers/specs/`

## 1. Problem

Action authors writing an `aiaction.yaml` manifest currently have no fast feedback loop: the manifest is only validated lazily by the runtime (`packages/runtime/src/runner/uses/...`) when something tries to load the package. Schema errors only surface during execution, often inside an `uses:` step in a downstream workflow, where the diagnostic is buried.

MS1.7 ships `aia action check`, a CLI verb that validates one or many manifests against `actionManifestSchema` and reports issues in an author-friendly form, with a stable exit code suitable for pre-commit hooks and CI.

## 2. Goals

- Authoring loop: validate any local `aiaction.yaml` in <100ms.
- CI-friendly: deterministic exit codes (`OK`, `SCHEMA`, `NOT_FOUND`, `USAGE`).
- Tooling-friendly: `--json` output with a forward-compatible shape that already reserves a `warnings` slot for the future linter (MS1.x).
- Respect the project's local-only constraint — pure local I/O, zero network.

## 3. Non-goals (explicit YAGNI)

- **Cross-file validation.** No `fs.stat` on paths referenced inside the manifest (e.g. `runs.node.entry`, `meta.icon`). Schema-only — see §6 Q4.
- **Lint-style warnings.** No detection of "input declared but unused", "missing description", etc. The `warnings: []` slot in `CheckResult`/`CheckJsonShape` is reserved but always empty in MS1.7. See §6 Q3.
- **Line/column diagnostics.** Errors carry zod path (`runs.using`, `meta.tags[1]`) only — no YAML CST / line numbers. Future enhancement; not blocking authors.
- **Auto-discovery in cwd.** `aia action check` (no args) is a `UsageError`, not a default scan. `--all` is the explicit batch form.
- **NDJSON streaming.** `--json` emits one JSON object covering all files. No streaming.
- **New public API in `@aiactions/workflows`.** Validation wrapping lives in `@aiactions/cli`; the workflows package keeps its current throwing `parseActionManifest` API.

## 4. UX

### 4.1 CLI surface

```
aia action check <path>
aia action check --all
aia action check <path> --json
aia action check --all --json
```

- `<path>` and `--all` are mutually exclusive. Both missing or both present → `UsageError` with exit code `USAGE` (2).
- `<path>` is a path to a single `aiaction.yaml`. Relative paths are resolved against `cwd`.
- `--all` walks `<cwd>` recursively, collecting every file whose basename equals `aiaction.yaml`. Any path containing a segment in `{"node_modules", ".git", "dist"}` is skipped (hardcoded — KISS). Empty result with `--all` → exit `NOT_FOUND` (4).
- `--json` switches output to a single JSON object on stdout (see §4.3). Default is human-readable.

### 4.2 Human output

Mono-path, valid:

```
✓ ./actions/foo/bar/aiaction.yaml — manifest valid
```

Mono-path, invalid:

```
✗ ./actions/foo/bar/aiaction.yaml — 2 errors
  ./actions/foo/bar/aiaction.yaml: schemaVersion: Invalid literal value, expected 1
  ./actions/foo/bar/aiaction.yaml: runs.main: runs.main must be a './...'-relative .mjs/.js path with no '..' segments or backslashes
```

`--all`, all valid:

```
✓ 4 manifests valid
  ./actions/claude/agent/aiaction.yaml
  ./actions/anthropic/sonnet/aiaction.yaml
  ./actions/openai/o1/aiaction.yaml
  ./actions/test/x/aiaction.yaml
```

`--all`, mixed:

```
✓ ./actions/claude/agent/aiaction.yaml — manifest valid
✓ ./actions/anthropic/sonnet/aiaction.yaml — manifest valid
✗ ./actions/test/x/aiaction.yaml — 1 error
  ./actions/test/x/aiaction.yaml: name: action name must be kebab-case

Summary: 2 valid, 1 invalid
```

Stream conventions:

- Successful "manifest valid" lines and the `Summary:` line: `stdout`.
- Per-issue error lines (the `<path>: <zodPath>: <message>` lines under a `✗` heading): `stderr`.
- Output via `process.stdout.write` / `process.stderr.write` directly (matches the existing `list.ts` / `install.ts` pattern; no `consola` dependency in this command).

Path display: relative to `cwd` if the manifest is inside `cwd`, otherwise absolute.

### 4.3 JSON output (`--json`)

Single JSON object on `stdout`. Schema:

```ts
interface CheckJsonShape {
  readonly ok: boolean;
  readonly files: ReadonlyArray<{
    readonly path: string; // absolute path
    readonly ok: boolean;
    readonly errors: ReadonlyArray<{
      readonly zodPath: string; // "" for YAML/IO errors
      readonly message: string;
    }>;
    readonly warnings: ReadonlyArray<{
      readonly zodPath: string;
      readonly message: string;
    }>; // always [] in MS1.7 — reserved for MS1.x linter
  }>;
}
```

`ok` at the top level is `files.every(f => f.ok)`. Paths are absolute in JSON (parseable by callers without CWD coupling).

### 4.4 Exit codes

`exit-codes.ts` adds:

```ts
SCHEMA: 7,
```

Matrix:

| Case                                        | Exit code       |
| ------------------------------------------- | --------------- |
| Mono `<path>` valid                         | `OK` (0)        |
| Mono `<path>` zod schema fail               | `SCHEMA` (7)    |
| Mono `<path>` malformed YAML                | `SCHEMA` (7)    |
| Mono `<path>` file does not exist           | `NOT_FOUND` (4) |
| `--all` all valid                           | `OK` (0)        |
| `--all` 1+ invalid                          | `SCHEMA` (7)    |
| `--all` zero manifests found under `cwd`    | `NOT_FOUND` (4) |
| Args missing/mutex (no path AND no `--all`) | `USAGE` (2)     |

Decision: `SCHEMA` covers both YAML malformation and zod failures (Q6.B). The author reads the message ("malformed YAML in '...'": vs "invalid enum value '...'") to disambiguate; a separate exit code adds noise without action value.

## 5. Architecture

```
@aiactions/workflows
  └─ parseActionManifest(path)                    [existing — throws WorkflowParseError | WorkflowSchemaError]

@aiactions/cli
  src/
    commands/action/check.ts                       [NEW — defineCommand, args → discovery → render → exit]
    lib/check-manifest.ts                          [NEW — checkManifest(path) → CheckResult, never throws]
    lib/format-issues.ts                           [NEW — formatIssue(issue, path) → string]
    lib/exit-codes.ts                              [EDIT — EXIT.SCHEMA = 7]
    cli.ts                                         [EDIT — register `action check` sub-command]
```

### 5.1 Why a helper file (`lib/check-manifest.ts`)

The CLI command file stays thin (arg parsing, discovery, rendering, exit). Validation logic lives in `lib/check-manifest.ts`, mirroring the existing `lib/walk-cache.ts` / `lib/registry.ts` / `lib/parse-short-ref.ts` layout. Three benefits:

1. Unit-testable without spawning the CLI or stubbing `citty`.
2. The returned `CheckResult` shape is also the per-file shape inside `CheckJsonShape` — no double mapping in the renderer.
3. `warnings: Issue[]` is in the type from day one, so the MS1.x linter slots in without changing any signature.

`@aiactions/workflows` is **not** modified — `parseActionManifest` keeps its throwing API (used by the runtime resolver and the workflow parser).

### 5.2 Types

```ts
// packages/cli/src/lib/check-manifest.ts
export interface Issue {
  readonly zodPath: string; // "runs.using" | "meta.tags[2]" | "" (YAML/IO error)
  readonly message: string;
}

export interface CheckResult {
  readonly path: string; // absolute path
  readonly ok: boolean;
  readonly errors: Issue[];
  readonly warnings: Issue[]; // always [] in MS1.7
}

export async function checkManifest(path: string): Promise<CheckResult>;
```

```ts
// packages/cli/src/lib/format-issues.ts
export function formatIssue(issue: Issue, path: string): string;
// "<rel>: <zodPath>: <msg>"  (zodPath omitted when "" → "<rel>: <msg>")
```

```ts
// packages/cli/src/commands/action/check.ts
interface CheckArgs {
  readonly path?: string;
  readonly all: boolean;
  readonly json: boolean;
}
```

### 5.3 Discovery (`--all`)

Local helper inside `check.ts`:

```ts
async function walkActionManifests(root: string): Promise<string[]>;
// fs.readdir(root, { recursive: true }), filter basename === "aiaction.yaml",
// skip any path that contains a segment in {"node_modules", ".git", "dist"}.
```

Node 22 builtin `fs.readdir(..., { recursive: true })` removes the need for `fast-glob`. Skip prefixes are hardcoded (KISS); `.gitignore` parsing is out of scope.

### 5.4 Error mapping

Inside `checkManifest`:

```ts
try {
  await parseActionManifest(path);
  return { path, ok: true, errors: [], warnings: [] };
} catch (err) {
  if (err instanceof WorkflowSchemaError) {
    const zodErr = err.cause as ZodError;
    return {
      path,
      ok: false,
      errors: zodErr.issues.map((i) => ({
        zodPath: joinZodPath(i.path), // ["runs", "main"] → "runs.main"
        // ["inputs", "foo", "default"] → "inputs.foo.default"
        message: i.message,
      })),
      warnings: [],
    };
  }
  if (err instanceof WorkflowParseError) {
    if (isENOENT(err.cause)) {
      throw new NotFoundError(`manifest not found: ${path}`);
    }
    return {
      path,
      ok: false,
      errors: [{ zodPath: "", message: err.message }],
      warnings: [],
    };
  }
  throw err; // unknown — bubble up
}
```

`NotFoundError` already exists in `lib/errors.ts` (extends `CliError`, exit `NOT_FOUND`). `isENOENT(cause)` checks `(cause as NodeJS.ErrnoException)?.code === "ENOENT"`.

`joinZodPath` joins string segments with `.` and number segments with `[N]`, producing `runs.using` and `meta.tags[1]` rather than the raw `runs.using` / `meta.tags.1` zod default.

## 6. Locked decisions (brainstorm 2026-05-08)

- **Q1 — Scope**: mono-path **+** `--all`. No silent auto-discovery on bare `aia action check`.
- **Q2 — Error format**: zod-path style `<file>: <zodPath>: <message>`. No YAML line/col in MS1.7.
- **Q3 — Warnings**: errors-only ship; `warnings: Issue[]` reserved (always `[]`) for forward compat with MS1.x linter.
- **Q4 — Validation depth**: schema-only. No `fs.stat` on referenced relative paths.
- **Q5 — `--json`**: single object `{ ok, files: [{ path, ok, errors, warnings }] }`. Forward-compatible with warnings.
- **Q6 — Exit + success output**: per-file success line always printed; one shared `EXIT.SCHEMA = 7` for YAML malformation and zod failures.

## 7. Testing strategy

Tests are written when they catch a real failure mode (per `.claude/rules/collaboration.md`). No tautological assertions, no implementation-coupled mocks.

```
packages/cli/tests/check-manifest.test.ts        # unit: lib/check-manifest
  - valid manifest                       → { ok: true, errors: [] }
  - malformed YAML                       → { ok: false, errors[0].zodPath === "" }
  - schema fail with N issues            → errors.length === N, joinZodPath segments are dot-joined (string keys) and bracket-wrapped (numeric keys)
  - file does not exist (ENOENT)         → throws NotFoundError (separate exit path)

packages/cli/tests/format-issues.test.ts          # unit: lib/format-issues
  - issue with zodPath                   → "<rel>: <zodPath>: <msg>"
  - issue with empty zodPath             → "<rel>: <msg>"  (no double colon)
  - absolute path inside cwd             → relativized

packages/cli/tests/check.test.ts                  # cli (direct run, no spawn)
  - missing args                         → UsageError, EXIT.USAGE
  - mutex (path + --all)                 → UsageError
  - --json valid                         → CheckJsonShape, ok: true
  - --json invalid                       → ok: false, errors populated, exit SCHEMA
  - --all walks tmp cwd                  → aggregated result over fixtures

packages/cli/tests/bin-integration.test.ts        # extend (1-2 cases)
  - aia action check ./valid.yaml        → exit 0, success line on stdout
  - aia action check ./invalid.yaml      → exit 7, error lines on stderr
```

Fixtures: `packages/cli/tests/fixtures/manifests/`:

- `valid.yaml` — minimal manifest passing `actionManifestSchema`.
- `invalid-schema.yaml` — produces ≥2 zod issues (e.g. wrong enum + wrong array element type).
- `malformed.yaml` — broken YAML syntax.

Skipped (intentionally):

- "Test that zod issues are passed through verbatim" — would test zod, not our code.
- "Test that consola goes to the correct stream" — flaky, env-dependent.
- Mocking `parseActionManifest` — couples tests to implementation; behaviour-level tests via fixtures cover the contract.

## 8. Out-of-scope follow-ups (parked)

These items are real but explicitly deferred so MS1.7 ships small:

1. **Path-existence checks** for relative paths inside the manifest (`runs.node.entry`, `meta.icon`). Adds value but couples the checker to current schema shape.
2. **Lint-style warnings** (unused inputs, missing description, etc.). The shape is reserved; the rules are not.
3. **YAML line/col diagnostics**. Requires switching to a parser that retains positions (`yaml` lib CST mode) and re-locating the offending zod path inside the document.
4. **Pre-commit / CI integration recipe** under `docs/`. Not a code change; can land alongside the next user-facing release.

## 9. Risk and rollback

- **Risk**: zod path joining edge cases (numeric path segments, empty-string keys, nested arrays). Mitigated by explicit unit test on `joinZodPath` covering both string and numeric segments.
- **Risk**: `fs.readdir(..., { recursive: true })` follows symlinks by default in Node 22 — could enter loops. Mitigation: pass `withFileTypes: false` and rely on basename filter; if a real loop is reported, switch to a manual recursion with cycle detection.
- **Rollback**: revert the merge commit. No DB, no shared state, no on-disk format. The `EXIT.SCHEMA = 7` constant is additive. The new `action check` sub-command is independent of existing verbs.
