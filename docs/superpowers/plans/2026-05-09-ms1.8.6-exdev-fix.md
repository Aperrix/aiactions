# MS1.8.6 — EXDEV fix in `fetchActionFromCanonical` — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Eliminate `EXDEV` failures in `fetchActionFromCanonical` by defaulting `tmpRoot` to `<registryRoot>/.tmp/`, so the clone+rename pipeline always stays intra-filesystem.

**Architecture:** Single-line default change in `packages/runtime/src/runner/uses/registry-fetch.ts`, plus an invariant-style regression test that asserts the new default location. No public API change. No copy fallback needed.

**Tech Stack:** TypeScript (strict), Vitest via `vite-plus/test`, Node `fs/promises`. Project toolchain: Vite+ (`vp`).

## Task 1: Add failing regression test for the default `tmpRoot` location

**Files:**

- Modify: `packages/runtime/tests/runner-uses-registry-fetch-fetch.test.ts` — append one new `test(...)` inside the existing `describe.skipIf(!POSIX)("fetchActionFromCanonical", …)` block.

- [ ] **Step 1: Append the failing test**

Insert this test as the last child of the existing `describe(...)` block, after the
"does not leave a partial directory at the cache path on failure" test (just before
the closing `});` at line 90):

```ts
test("defaults tmpRoot to <registryRoot>/.tmp when no tmpRoot is provided", async () => {
  const work = await mkdtemp(join(tmpdir(), "aiactions-fetch-"));
  const bareRepo = await makeBareRepoWithAction({
    cwd: work,
    namespace: "octocat",
    name: "lint",
    tag: "octocat/lint@v1.0.0",
    manifest: "name: lint\ndescription: lint things\nruns:\n  using: node\n  main: index.mjs\n",
    sources: { "index.mjs": "export default async () => {};\n" },
  });

  const registryRoot = join(work, "registry");
  await fetchActionFromCanonical(
    { namespace: "octocat", name: "lint", version: "1.0.0" },
    registryRoot,
    { canonicalUrl: `file://${bareRepo}` }, // intentionally omits tmpRoot
  );

  const tmpStat = await stat(join(registryRoot, ".tmp"));
  expect(tmpStat.isDirectory()).toBe(true);
});
```

The test passes the same fixture pattern used by sibling tests but **omits `tmpRoot`**, forcing the helper to use its default. After the call returns, it asserts `<registryRoot>/.tmp/` exists as a directory — which is only possible if the helper resolved its default to that location and ran `mkdir(tmpRoot, { recursive: true })`.

- [ ] **Step 2: Run the test and verify it fails**

Run from `packages/runtime`:

```bash
vp test runner-uses-registry-fetch-fetch
```

Expected: the new test FAILS. Reason: with the current default `tmpRoot = osTmpdir()`, the helper creates its tmp dir under `os.tmpdir()` (e.g. `/tmp`). It also throws `EXDEV` on Linux Fedora when the rename crosses filesystems — so the test will likely fail at the `rename` step (the `stat(join(registryRoot, ".tmp"))` will never run), with an error like `ENOTSUP: cross-device link not permitted, rename '/tmp/...' -> '<registryRoot>/octocat/lint/1.0.0'`. On a host where `/tmp` and `$HOME` share a filesystem, the test still fails — `<registryRoot>/.tmp` is never created, and `stat` rejects with `ENOENT`.

Either failure mode is acceptable evidence that the test is currently red.

- [ ] **Step 3: Commit the failing test**

```bash
git add packages/runtime/tests/runner-uses-registry-fetch-fetch.test.ts
git commit -m "test(runtime): cover default tmpRoot location in fetchActionFromCanonical"
```

## Task 2: Switch the default `tmpRoot` to `<registryRoot>/.tmp/`

**Files:**

- Modify: `packages/runtime/src/runner/uses/registry-fetch.ts` (the single line that
  defaults `tmpRoot` inside `fetchActionFromCanonical`).

- [ ] **Step 1: Apply the one-line default change**

Open `packages/runtime/src/runner/uses/registry-fetch.ts` and find the line inside
`fetchActionFromCanonical` (currently line 135) that reads:

```ts
const tmpRoot = options.tmpRoot ?? osTmpdir();
```

Replace it with:

```ts
const tmpRoot = options.tmpRoot ?? join(registryRoot, ".tmp");
```

`join` is already imported at the top of the file (used elsewhere in the same function).

- [ ] **Step 2: Update the option docstring**

The `FetchActionFromCanonicalOptions.tmpRoot` JSDoc (currently lines 106-108) reads:

```ts
  /** Parent directory used for the throwaway clone. Defaults to
   * `os.tmpdir()`. */
  readonly tmpRoot?: string;
```

Replace with:

```ts
  /** Parent directory used for the throwaway clone. Defaults to
   * `<registryRoot>/.tmp/`, which guarantees the clone shares a
   * filesystem with the destination so the final `rename` stays
   * atomic and EXDEV-free. */
  readonly tmpRoot?: string;
```

- [ ] **Step 3: Remove the now-unused `osTmpdir` import**

After Steps 1-2, `osTmpdir` should have exactly one reference left — the import on line 14:

```ts
import { tmpdir as osTmpdir } from "node:os";
```

Verify with:

```bash

```

Expected: a single line of output for the import on line 14. Delete that line.

- [ ] **Step 4: Run the regression test and verify it passes**

```bash

```

Expected: all tests in the file pass, including the new `defaults tmpRoot to <registryRoot>/.tmp …` case.

- [ ] **Step 5: Run the full registry-fetch suite to ensure nothing else regressed**

This runs both `runner-uses-registry-fetch.test.ts` (covers `ensureCachedAction`) and `runner-uses-registry-fetch-fetch.test.ts`. Expected: all pass. If `ensureCachedAction` tests pass an explicit `tmpRoot`, they keep working unchanged.
